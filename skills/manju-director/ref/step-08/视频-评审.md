> 加载时机：视频环节「08-1 视频」子步骤产出后执行评审时。评审规则不符即打回。关联文档：ref\step-08\视频.md（本子步骤执行流程主线）、ref\step-08\template\视频提示词模板.md（双文件两段式）。

> **不请用户审核**：08-2 视频评审通过后**不提交用户审核**，直接进入 08-3 放大（放大完成后按流程继续后续环节）。

# 视频评审（step_08 · 08-2 视频评审）

## 一、评审能力边界（能做 / 做不了 / 必做）

### ✅ 能做（自动核对类，逐项必做）
评审可以且必须自动核对以下各项（均为确定性的文件/内容核验，可逐条执行）：
- 文件与命名核对：video 三件套一一匹配（`videoX.mp4` + `视频X提示词_cn.md` + `视频X提示词_en.md`）、镜头与分镜一一对应、临时文件归 `temp\`
- 提示词结构与内容核对：**双文件（cn/en 分离）**、分段时间轴、@xx 模块式、空间逻辑描绘、空间方位、运镜三要素、发声约束、人物一致性
- 参数文件核对：`镜头X_分镜参数.json` + `镜头X_视频参数.json` 齐备且内容真实
- 工作流与参考媒体排定核对：只用 15.MinimaxH3 多图参考01~20、media_1=本镜状态+朝向匹配的场景组合图、禁止合并角色图
- 真实产物判定：空文件/占位文件一律视为未完成
- AIGC 溯源块与文字水印扫描清理（全流程必查）
- 立项字段一致性核对

### ❌ 做不了（需视觉审图能力，当前模型不支持时不做）
- 实际画面质量 / 运镜流畅度 / 口型同步 / 人物一致性**视觉效果** / 画面美学
- 模型不具备视觉审图能力时：**不做内容审查**，明确提醒用户自行审查；**禁止**退化为"数量/命名核对"假装已完成评审
- 模型具备视觉审图能力时：按第四章「内容审查」执行

### ⚠️ 必做（硬性，缺一不可）
- 上述「能做」的自动核对项**全部逐项执行**，禁止选择性跳过；任一项不符即按「打回规则」处理
- 硬闸项目（真实产物、AIGC/水印、工作流选档、分段时间轴）不符即打回，不得放行

## 二、评审流程与打回规则
1. 读取 `00_项目\评审\` 下对应环节的评审结论
2. decision = "approved" → 放行，进入 08-3 放大
3. decision = "revision" → 记录问题清单 → 调度 08-1 视频重做
4. decision = "escalated" → 最高级，通知用户决策
5. **打回规则**：同一环节最多打回 5 次；第 6 次仍不通过，升级给用户决策，不得无限打回

## 三、必做评审项（逐项验证，不符即打回）

> 评审项按视频.md 的 6 步主线归组，便于对照定位问题出在哪个环节。

### A. 工作流与参考媒体排定（对应步骤1/2）
1. **工作流 = 15.MinimaxH3 多图参考01~20（按N自动选档）**：视频环节只使用 `15.MinimaxH3 多图参考{N:02d}.json`（N=1~20）按本镜参考图数量 N 自动选档这一组工作流，不得出现其他档位/备选；参考图排定 = **media_1 本镜状态+朝向匹配的场景组合图（`04_图片\场景\`，命名`场景名-状态-面`如 `xx小屋-白天-镜头朝东.jpg`，禁止沿用上个视频末帧）+ media_2~N 角色（每角色独立单图，严禁合并角色图）→ 场景 → 道具**，N≤20，从 media_2 起连续占用不跳号；多图参考01~20 系列无音频槽；旧 10.x（RH Ref2VA，实测报错不可用）/12.1/12.2/14 全部废弃，不得出现

### B. 提示词文件与格式（对应步骤4）
2. **每个镜头有视频提示词 CN/EN 双文件 `视频X提示词_cn.md` + `视频X提示词_en.md` 且内容真实**：生成模式统一 **15.MinimaxH3 多图参考{N:02d}**（N=参考图数量 1~20，按N自动选档）；参考媒体清单（media_1=本镜状态+朝向匹配的场景组合图（`04_图片\场景\`，命名`场景名-状态-面`，禁止沿用上镜末帧）+ media_2~N 角色每角色独立单图/场景/道具，N≤20）；en 文件含 @xx 模块式（subject_definitions 用 @图片N 定义主体、retention_analysis 逐主体保真、detailed_description 分镜逐段+台词中文原句、overall_soundscape 环境音效）；含画面内容、动作、时长
3. **双文件两段式结构（参照角色方案）**：cn 文件 = `# 提示词：视频X（镜头X）cn` + `# 正向提示词`（`## 风格` / `## 布局` / `## 详细描述`）+ `# 反向提示词`；en 文件 = `# Video Prompt: Video X (Shot X) en` + `# Positive Prompt`（`## Style:` / `## Layout:` / `## Detailed Description:`）+ `# Negative Prompt`。**严禁单文件多段式**（违者 Revise）
4. **en 的 `## Detailed Description` 段为提交逐字全文**：@xx 模块式英文（subject_definitions / @ / summary / retention_analysis / detailed_description / overall_soundscape / 可选 non_diegetic_music）即提交 video_gen.py 的 prompt 全文；提交后须回填校验一致，禁止"文档一套、提交另一套"
5. **单式角色也用 @ 模块式**：单式角色镜头（如自我介绍短视频）提示词同样必须用 subject_definitions（<Subject 1> is ... from @图片1）+ @ 分隔 + summary/retention_analysis/detailed_description/overall_soundscape 模块式骨架，禁止退化成无 @ 引用的纯描述单式段落
6. **分段时间轴强制**：cn 详细描述含【镜头X｜起止s｜景别｜机位｜运镜】分段 + 「台词 00:MM.SS-00:MM.SS：原文」绝对起止标注 + 静默开场/静默收尾；EN detailed_description 含台词起止时刻（如 At 00:05.500）；缺时间轴 → Revise
7. **空间逻辑描绘**：视频提示词必须含"【空间逻辑描绘】"段，且取用对应场景提示词文件**详细描述段**的"空间逻辑描述点"（空间逻辑描述点并入详细描述段，不单独成段）+分镜空间方位（人物相对标志物位置/运动路径/前后景/视线关系/进出场方向）；缺项或逻辑矛盾 → Revise
8. **运镜三要素标注齐全**：每个提示词文件必写"景别+机位+运镜"；**默认固定机位**（写"相机完全静止,无推拉摇移,无晃动"）；特殊运镜须与分镜运镜标注一致且有动机（违者 Revise）
9. **空间方位原样引用**：提示词文件必须含"【空间方位】"段且与分镜空间方位一致（①标志物位置②人物站位③运动方向④不在场说明）；缺项或与分镜不一致 → Revise
10. **发声约束（无台词镜头）**：分镜台词为"无"的镜头，提示词必须写"画面全程无声，人物不产生任何语言"；禁止出现"如模型产生语音必须是普通话"这类暗示有语音的句子（违者 Revise）
11. **人物一致性约束写入提示词**：每个提示词文件必须写明"角色严格保持参考图 `@图片N` 的发型/发色/服装/体型/五官不变,不得换人"（subject_definitions/retention_analysis 逐主体引用）；多角色逐一点名描述（违者 Revise）

### C. 参数文件（对应步骤1/2）
12. **每镜有 视频参数.json + 分镜参数.json**：`镜头X_视频参数.json`（生成后实际提交参数）+ `镜头X_分镜参数.json`（从分镜提取的镜头参数）；缺失 → Revise

### D. 提交与取回（对应步骤5）
13. **任务状态轮询痕迹（真实联调后）**：每次提交有 `prompt_id` 记录；失败（`status_str=="error"`）有重试记录；成功后才取产物（评审可凭 prompt_id 复查；轮询/失败判定见本技能 9.4 接口规范）

### E. 产物完整性与一一对应（对应步骤5/6）
14. **镜头与分镜一一对应**：数量/时长匹配（每镜5~10s）；视频文件命名 `videoX.mp4` 与分镜编号一致
15. **画面内容与分镜一致**：对核对象 = **视频提示词文件**（多角色镜头每角色独立参考图、顺序与提示词一致；单人镜头单图参考）
16. **画面含环境音效（随画面生成）；不含BGM/配音**：以提示词文件标注为准（多图参考01~20 系列无音频槽，环境音靠提示词 overall_soundscape 文字描述随画面生成）
17. **画面含角色开口原声（有台词镜头）**：角色开口说话，供声线Agent（step-05）视频取声线种子、供 step-09 配音环节实测定位台词——以提示词台词时间轴标注为准（**台词文本与时间轴 = 分镜台词时间轴,不得改写**）；**独白镜头（仅一角色说话）有 `【独白镜头】` 标记**，供声线Agent选种子
18. **有台词角色必须管理**：凡开口说话的角色（哪怕一句台词、一次性出场如记者/群众个体）必须已提取资产并参与一致性与配音评审；仅**无台词**的纯路人群像由视频自由生成，本项不核查一致性、不强制标注
19. **片头片尾画面模板仅立项勾选时产出**（存放 `05_视频\片头片尾\`）
20. **临时文件放 temp\**

### F. 立项一致性与真实产物（全流程硬闸）
21. **立项字段一致性**：每个环节的产出都必须符合 `00_项目\立项.md` 中导演引导确认的立项项（美术风格/画幅/配音语言/片头片尾等），不符合视为 Revise
22. **真实产物判定**：所有产物必须为真实生成文件，空文件/占位文件一律视为未完成 → Revise，不得放行；接口未联调导致无法真实产出时，该环节标记"阻塞"，报告导演与用户，不得以空文件充数

### G. AIGC 溯源块与水印零容忍（全流程必查）
23. **AIGC溯源块与水印零容忍**：评审必须扫描并清理 AIGC 溯源块（`AIGC:` / Label / ContentProducer / ProduceID / ReservedCode1 / ContentPropagator / PropagateID / ReservedCode2）与文字水印（内容由AI生成，仅供参考）。发现即打回要求删除，不得放行——带 AIGC 块的产物无法通过抖音平台审核。全流程各环节评审必查。

### H. 引用一致性（全流程）
24. **引用一致性**：任何环节不得擅自改写资产文件中的外貌/声线；时长换算使用 `本技能 timing.md`

## 四、内容审查（仅当前模型支持时执行）
- 实际画面质量/运镜/口型同步/人物一致性视觉效果 → 需当前模型具备视觉审图能力时执行
- 模型不支持内容审查时：**不做内容审查，提醒用户自行审查**；**不允许退化为数量/命名核对**

## 五、不一致处理
画面内容/空间方位/运镜/人物一致性与分镜或 `立项.md` 不一致 → 先提醒用户是否继续，不主动继续/放行
