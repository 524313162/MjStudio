# 视频·放大（step_08 · 08-3 放大，视频放大到 1K）

## 1. 环节职责与边界

### 1.1 职责
对 08-1 视频环节产出的**全部正片 `videoX.mp4`**，用 **`ref\step-08\workflows\17.视频放大1K.json`**（RealESRGAN 放大 + 1920x1080 缩放 + Video Combine）放大到 **1K（1920x1080，横屏 16:9）**，提升清晰度，作为最终成片画面源。提交细节全部由 `ref\step-08\scripts\upscale_gen.py` 封装，正常放大一律走脚本，**禁止临场手写工作流 / 逐节点填写**。

### 1.2 放大规则（铁律）
- **全量放大**：本集**每一个** `videoX.mp4` 正片都必须放大，不得跳过/遗漏。**转场衔接片段已取消（2026-09-07 用户决策），不放大任何衔接片段**。
- **工作流固定**：放大只使用 `ref\step-08\workflows\17.视频放大1K.json`，不得替换/改档/新增其它放大工作流。
- **画幅固定**：放大输出固定 **1920x1080（16:9）**；本工作流节点4 `缩放图像` 已固定 1920x1080，横屏项目无需传画幅参数。若未来做竖屏（9:16）项目，需节点4改为 1080x1920（见 4.1 说明），当前横屏一律 1920x1080。
- **输出命名**：放大件落 `05_视频\第N集\`，命名 `videoX_1K.mp4`，与原正片一一对应。
- **原片保留**：放大件独立落盘，**不得覆盖/删除**原 `videoX.mp4`（原片为评审/回退/重出用）。

### 1.3 职责边界
- 本环节只做**放大（清晰度提升）**，不改变画面内容/时长/音轨，不剪辑、不混音、不配音。
- 放大在 08-2 视频评审通过后执行，放大件为合成环节（step-10）使用的画面源。

## 3. 固定命名规范（任何环节不得破坏）

- 全部落 `05_视频\第N集\`；原片保留在旁，不覆盖。

## 4. 执行流程

### 4.0 放大清单（开工第一步）
本集全部视频评审通过后，先盘点本集所有待放大件（正片 `videoX.mp4` 全量），产出 `放大清单.md` 落 `05_视频\第N集\`：
```markdown
待放大：video1.mp4 → video1_1K.mp4
待放大：video2.mp4 → video2_1K.mp4
...
```

### 4.1 放大脚本（upscale_gen.py，逐片直调）

> 直接调用封装脚本 `ref\step-08\scripts\upscale_gen.py`，按工作流 `ref\step-08\workflows\17.视频放大1K.json`（Load Video(1) → UpscaleModelLoader(2, RealESRGAN_x4plus_anime_6B) → ImageUpscaleWithModel(3) → ImageScale(4, 1920x1080 lanczos) → VideoCombine(5, upscaled_1K)）自动复制输入视频进 input、填节点、提交、轮询、从 output 源件取回。**禁止临场手写工作流 / 逐节点填写**。

**必填参数**：
- `--video "05_视频\第N集\videoX.mp4"`：待放大视频**绝对路径**（一次一个，逐片调用）。
- `--out-name videoX_1K`：放大件取回文件名（不含扩展名；含 `_1K` 后缀）。

**常用可选**：`--out-dir <05_视频\第N集>`（落盘目录，建议必给）、`--width 1920` / `--height 1080`（缩放目标，默认 1920x1080；竖屏项目改 1080x1920）、`--prefix manju_up`（input 复制前缀，默认 manju_up）、`--dry-run`（只构造不提交，先看填槽/取回逻辑）。

**调用示例**：

```
python upscale_gen.py --video "G:\ManJu\05_视频\第1集\video1.mp4" --out-name video1_1K --out-dir "G:\ManJu\05_视频\第1集"
```

> 提示：全部正片逐一放大（衔接片段已取消，无需放大）。取回铁律同 video_gen.py：从 ComfyUI output 源件 Copy-Item 取回（禁 8188/view 下载，会带水印）。
