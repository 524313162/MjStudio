> 加载时机：剧本环节产出后执行评审时。评审规则不符即打回。

## 一、评审流程与打回规则
1. 读取 `00_项目\评审\` 下对应环节的评审结论
2. decision = "approved" → 放行，进入下一环节
3. decision = "revision" → 记录问题清单 → 调度对应环节重写
4. decision = "escalated" → 最高级，通知用户决策
5. **打回规则**：同一环节最多打回 5 次；第 6 次仍不通过，升级给用户决策，不得无限打回

## 二、评审规则（必须逐项验证，不符即打回）
1. **每集时长 ≥ 2 分钟**（硬指标，按 `本技能 timing.md` 公式逐项自算，剧本内附自算明细）
2. **本集角色列表完整**：本集全部出场角色均列出，含一次性有台词角色与旁白（供分镜环节提取资产）
3. **台词量匹配画面节奏**：不多不少、旁白克制（旁白不算配音泛滥；旁白列入本集角色列表）
4. **片头/片尾标注**（仅立项勾选片头片尾时才有）
5. **立项字段一致性**：每个环节的产出都必须符合 `00_项目\立项.md` 中导演引导确认的立项项（美术风格/画幅/配音语言/片头片尾等），不符合视为 Revise
6. **真实产物判定**：所有产物必须为真实生成文件，空文件/占位文件一律视为未完成 → Revise，不得放行；接口未联调导致无法真实产出时，该环节标记"阻塞"，报告导演与用户，不得以空文件充数
7. **AIGC溯源块与水印零容忍**：评审必须扫描并清理 AIGC 溯源块（`AIGC:` / Label / ContentProducer / ProduceID / ReservedCode1 / ContentPropagator / PropagateID / ReservedCode2）与文字水印（内容由AI生成，仅供参考）。发现即打回要求删除，不得放行——带 AIGC 块的产物无法通过抖音平台审核。全流程各环节评审必查。
8. **引用一致性**：任何环节不得擅自改写资产文件中的外貌/声线；剧本可供分镜直接拆分引用，角色行为符合世界观；时长换算使用 `本技能 timing.md`

## 三、内容审查（仅当前模型支持时执行）
- **故事完整**：起承转合齐全（起因→发展→转折→结果/钩子），不能是片段
- 每章 ≥ 1 个剧情热点（冲突/转折/钩子/笑点/泪点）
- 角色行为符合世界观，剧情符合 `立项.md` 的世界观设定
- 模型不支持内容审查时：不做内容审查，提醒用户自行审查；**不允许退化为数量/命名核对**

## 四、不一致处理
剧情/角色/时长任一与 `立项.md` 或内容不一致 → 先提醒用户是否继续，不主动继续/放行

## 五、输出格式
```markdown

结论: ✅ Pass / ❌ Revise
问题清单:
- RV-01: [问题描述](期望 vs 实际)
- RV-02: ...
建议: (打回给哪个Agent / 升级用户)
```
